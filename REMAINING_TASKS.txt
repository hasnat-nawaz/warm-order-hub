        WARM ORDER HUB – REMAINING TASKS (Manual / External Setup)
                     SE202L Semester Project
================================================================================

The following tasks CANNOT be completed inside the code repository alone.
They require external accounts, cloud services, and manual configuration.
Complete them in order.

================================================================================
 1. GITHUB REPOSITORY SETUP
================================================================================

   a) Create a GitHub repository (if not already done):
      - Go to https://github.com/new
      - Name: warm-order-hub (or your chosen name)
      - Set visibility as needed

   b) Push the code to GitHub:
      > git remote add origin https://github.com/<your-username>/warm-order-hub.git
      > git branch -M main
      > git push -u origin main

   c) Ensure ALL group members have contributed commits:
      - Each member should clone the repo, make changes, and push
      - Commits must be distributed over time (not all at once)
      - Use feature branches and merge via pull requests

   d) Branching & Merging:
      - Create feature branches for each task (e.g., feature/docker, feature/cicd)
      - Merge into main via pull requests
      - This demonstrates proper Git workflow for grading

================================================================================
 2. CONFIGURE GITHUB SECRETS (for CI/CD deployment)
================================================================================

   Go to: GitHub Repo → Settings → Secrets and variables → Actions

   Add these repository secrets:

   ┌──────────────┬──────────────────────────────────────────────────┐
   │ Secret Name  │ Value                                            │
   ├──────────────┼──────────────────────────────────────────────────┤
   │ EC2_HOST     │ Public IP address of your EC2 instance           │
   │ EC2_USER     │ SSH username (usually "ubuntu" for Ubuntu AMI)   │
   │ EC2_SSH_KEY  │ Full content of your .pem private key file       │
   └──────────────┴──────────────────────────────────────────────────┘

   NOTE: You must complete Step 3 (AWS EC2 setup) first to get these values.

================================================================================
 3. AWS EC2 INSTANCE SETUP
================================================================================

   a) Create an AWS account (if you don't have one):
      - https://aws.amazon.com/free (free tier eligible)

   b) Create a Key Pair:
      - Go to: AWS Console → EC2 → Key Pairs → Create Key Pair
      - Name it (e.g., "warm-order-hub-key")
      - Download the .pem file and keep it safe

   c) Launch an EC2 Instance:
      - AMI: Ubuntu Server 22.04 LTS (free tier eligible)
      - Instance type: t2.micro (free tier)
      - Key pair: Select the one you created
      - Security Group: Allow inbound on ports:
          * 22   (SSH)
          * 80   (HTTP – frontend)
          * 8080 (Backend API)

   d) SSH into the instance:
      > chmod 400 your-key.pem
      > ssh -i your-key.pem ubuntu@<EC2_PUBLIC_IP>

   e) Install Docker on EC2:
      > sudo apt update && sudo apt upgrade -y
      > sudo apt install -y docker.io docker-compose-plugin
      > sudo systemctl enable docker
      > sudo usermod -aG docker $USER
      > exit
      (Log back in for group changes to take effect)

   f) Deploy the application:
      > git clone https://github.com/<your-username>/warm-order-hub.git
      > cd warm-order-hub
      > cp backend/.env.example backend/.env
      > nano backend/.env   (fill in production DATABASE_URL, JWT_SECRET, CLIENT_ORIGIN)
      > docker compose up -d --build

   g) Verify the app is running:
      - Open http://<EC2_PUBLIC_IP> in your browser (frontend)
      - Test http://<EC2_PUBLIC_IP>:8080/api/health (backend health check)

================================================================================
 4. UPDATE BACKEND .env ON EC2 FOR PRODUCTION
================================================================================

   Edit backend/.env on the EC2 instance:

   PORT=8080
   DATABASE_URL=<your-neon-postgres-connection-string>
   JWT_SECRET=<a-long-random-secret-string>
   CLIENT_ORIGIN=http://<EC2_PUBLIC_IP>

   NOTE: CLIENT_ORIGIN must point to the actual public IP/domain
   of your EC2 instance so CORS allows frontend requests.

================================================================================
 5. TERRAFORM SETUP (OPTIONAL – for bonus marks)
================================================================================

   If you want to automate EC2 provisioning with Terraform:

   a) Install Terraform:
      - https://developer.hashicorp.com/terraform/install

   b) Configure AWS CLI:
      > aws configure
      (Enter your AWS Access Key ID, Secret Access Key, and region)

   c) Use the provided Terraform config:
      > cd terraform
      > cp terraform.tfvars.example terraform.tfvars
      > nano terraform.tfvars   (set your key_name to the AWS key pair name)
      > terraform init
      > terraform plan
      > terraform apply

   d) Note the outputs (public IP, SSH command) for GitHub Secrets setup.

 6. DOCKER IMAGE REGISTRY (OPTIONAL)
================================================================================

   If you want to push images to Docker Hub or AWS ECR:

   a) Docker Hub:
      > docker login
      > docker tag warm-order-hub-backend <dockerhub-user>/warm-order-hub-backend
      > docker push <dockerhub-user>/warm-order-hub-backend
      > docker tag warm-order-hub-frontend <dockerhub-user>/warm-order-hub-frontend
      > docker push <dockerhub-user>/warm-order-hub-frontend

   b) To add this to CI/CD, add DOCKER_USERNAME and DOCKER_PASSWORD
      as GitHub Secrets and update the workflow accordingly.
